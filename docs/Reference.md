# 工程师个人网站参考

## 值得优先拆解

- **Rauno** — https://rauno.me/：首页把个人身份、数字花园、开源与文章放在同一入口；页面 meta 将其描述为“Software engineer and open source creator”以及“digital garden”。适合参考“长期积累型个人主页”。
- **Lee Robinson** — https://leerob.com/：个人介绍、项目、文章和社交入口组织得很清楚，信息密度高，适合参考 Next.js/React 工程师的产品化主页结构。
- **Josh W. Comeau** — https://www.joshwcomeau.com/：把文章、交互式技术演示、课程和邮件订阅组合成完整内容产品，适合参考博客与订阅转化。
- **Brittany Chiang** — https://brittanychiang.com/：以职业定位、经历、项目案例和联系入口为主线，适合参考求职/接项目导向的作品集。
- **Bruno Simon** — https://bruno-simon.com/：通过可操作的 3D 场景作为导航和自我介绍，适合研究“作品本身就是交互体验”的创意方向；需要注意加载、移动端和可访问性成本。
- **Cassie Evans** — https://cassie.codes/：把动效、实验、演讲和技术身份结合起来，适合参考创意开发者如何展示 motion/creative coding 能力。
- **Jhey Tompkins** — https://www.jhey.dev/：以实验、教程和可运行 Demo 为核心，适合参考“用小作品证明技术实力”的内容组织方式。
- **Swyx** — https://swyx.io/：个人介绍、文章、项目/社区活动和订阅入口并置，适合参考技术写作者与开发者关系经营。
- **Wes Bos** — https://wesbos.com/：课程、播客、文章、邮件列表和个人项目形成清晰的内容产品体系，适合参考 RSS/订阅/付费内容如何共存。
- **Kent C. Dodds** — https://kentcdodds.com/：文章、课程、演讲、订阅和社区资源组织成熟，适合参考专业可信度与长期内容归档。

## 额外观察

- **Overreacted** — https://overreacted.io/：极简博客入口和高识别度排版，适合参考文章阅读体验与 RSS 优先的内容站。
- **Paul Irish** — https://www.paulirish.com/：长期个人品牌、技术文章与公开履历的结合，适合参考个人档案的时间跨度和可信度。
- **Tania Rascia** — https://www.taniarascia.com/：教程、项目和个人介绍边界清晰，适合参考文档化写作和搜索友好结构。

## 对自己的站点最值得借鉴的组合

1. 首页只回答三件事：你是谁、擅长解决什么问题、最值得先看的项目是什么。
2. 项目页以“问题—方案—架构—关键取舍—结果—源码/演示—复盘”写案例，不要只放截图和技术栈标签。
3. 博客与项目共用内容模型：文章可关联项目，项目可反向链接设计决策、性能数据和源码。
4. RSS、邮件订阅、GitHub、LinkedIn/即刻等外部入口使用统一的订阅区，不要让首页出现多个互相竞争的 CTA。
5. 实用链接单独做“工具箱/书签”页面，支持标签、搜索和最后更新时间；它应是可持续维护的资源页，不要变成链接墓地。
6. 视觉上先建立一套稳定的排版、颜色、间距和动效规则，再加入 3D 或复杂交互；创意交互必须有普通导航和静态降级路径。
